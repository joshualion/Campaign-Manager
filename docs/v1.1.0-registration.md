# Community v1.1.0 installation and upgrade notes

Candidate documentation. v1.1.0 is not published yet; v1.0.9 and historical assets are preserved.

## Download and installation identity

Campaign Manager Community Edition remains free to download and self-host. Professional installation, managed hosting, maintenance, training and assisted upgrades are separate optional services.

The official website download form records first name, last name, email, selected version, referral source and request time. Promotions require a separate unchecked preference and confirmed email. A referral does not prove a successful file transfer or installation.

A consultant's download email may differ from the organisation's installation administrator. New v1.1.0 installation registration collects the Super Administrator email, configured public domain, random persistent installation UUID, software version, status and terms acceptance. The installer uses a dedicated portal credential, encrypted locally; the portal stores only its hash.

GitHub does not provide private downloader email addresses. Direct GitHub visitors can download official releases and will encounter registration during new installation.

## New installations

1. Use the official campaign-manager.zip package and verify its SHA-256 and signed manifest using the established trusted public key.
2. Meet the existing PHP/database/extension requirements and complete local installer ownership proof.
3. Configure the public installation domain and Super Administrator email.
4. Read the current licence and privacy notice and accept registration terms.
5. Choose optional promotions separately. The default is unchecked; no phone is required for registration.
6. Run installation. The official portal must acknowledge an identity-bound receipt before setup completes.

If registration fails, check the configured domain and outbound HTTPS to the official portal, then retry Run Installation. The installer preserves its UUID, encrypted credentials, configuration and existing records. Do not delete .env, replace the application key or reset the database as a retry workaround.

Contact confirmation is separate from the technical receipt. Until email confirmation and marketing opt-in are both satisfied, promotions remain ineligible. An accepted installation is not remotely locked out by a later temporary portal outage.

## Existing installations

Back up the database, environment, storage and uploads before upgrading. Preserve the application key and installation lock. Apply reviewed compatible migrations with php artisan migrate --force. Never use migrate:fresh, migrate:refresh or db:wipe on live installations.

Do not rerun the new-installation wizard over populated deployments. Existing installations complete the registration transition through Official Updates. Registration, configuration or connectivity problems do not silently disable established deployments.

For a domain migration, preserve the installation identity, request a change from Official Updates, confirm through the verified contact email and re-register that same identity on the new configured domain. Contact changes require verified ownership handling or support rather than unauthenticated replacement.

## Updates and assistance

Official release checking and signature-verified staging are supported by the candidate. Automatic update application and rollback are not included. Applying an update remains a manual maintenance procedure with a verified backup and code rollback plan.
