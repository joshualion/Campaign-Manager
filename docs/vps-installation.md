# Installing Campaign Manager on a VPS / Linux Server

This guide covers a conventional self-hosted deployment on a Linux VPS using Apache or Nginx concepts without assuming a particular distribution.

> Campaign Manager Community is free to download and use. No software licence key is required. QuickStart Geography Provisioning is optional.

## Architecture overview

A normal production deployment needs:

- Linux server
- supported PHP runtime and extensions
- Apache or Nginx
- MySQL/MariaDB-compatible database supported by the release
- HTTPS certificate
- Campaign Manager application directory
- web root pointed to `public/`
- correct ownership for writable Laravel directories
- backups and monitoring
- queue/scheduler processes if you enable features that require them

## 1. Prepare the server

Apply operating-system security updates and install the web server, PHP runtime, database client/server as appropriate, certificate tooling and basic operational tools.

### PHP version and extensions

The public repository does not expose Campaign Manager's private dependency manifest. Do not infer compatibility from a generic Laravel tutorial.

After deploying the release, use the installer **Requirements** step as the authoritative PHP/extension check for that release. Resolve any critical failure before continuing.

## 2. Create the application directory

A common layout is:

```text
/var/www/campaign-manager
```

Download the official `campaign-manager.zip` release asset from:

[GitHub Releases](https://github.com/joshualion/Campaign-Manager/releases/latest)

Extract it into the application directory.

The public web root must be:

```text
/var/www/campaign-manager/public
```

## 3. Create the database

Create a dedicated database and least-privileged application user with the permissions needed to manage the Campaign Manager schema.

Keep the following connection information available:

```text
DB_HOST
DB_PORT
DB_DATABASE
DB_USERNAME
DB_PASSWORD
```

Do not run the application under a database superuser account.

## 4. Configure the application environment

Where needed:

```bash
cd /var/www/campaign-manager
cp .env.example .env
```

Set the production URL, database, mail and other environment values through the installer/environment workflow.

If an application key has not already been generated by the installer:

```bash
php artisan key:generate
```

For production:

```text
APP_DEBUG=false
APP_URL=https://your-domain.example
```

Keep `.env` readable only by appropriate operating-system users.

## 5. Permissions and ownership

The PHP/web-server execution context must be able to write to:

```text
storage/
bootstrap/cache/
```

Prefer correct ownership and group permissions. Avoid `chmod 777`.

The exact commands depend on your distribution, web-server user and PHP-FPM pool. A typical pattern is to make the deployment owner responsible for the code and grant the web-server group controlled write access only where Laravel requires it.

## 6. Configure the web server

### Nginx concept

Set the site root to:

```text
/var/www/campaign-manager/public
```

Use `index.php` as an index and route non-file requests through Laravel's front controller. Configure PHP requests through the PHP-FPM socket/service that matches your supported PHP runtime.

Do not expose hidden files such as `.env`.

### Apache concept

Set `DocumentRoot` to:

```text
/var/www/campaign-manager/public
```

Allow Laravel's public-directory rewrite rules to operate. Ensure the appropriate rewrite module/configuration is enabled for your environment.

Do not configure the application root as the document root.

## 7. DNS and HTTPS

Point the domain to the VPS and issue a trusted TLS certificate.

Verify:

```text
https://your-domain.example
```

loads over HTTPS and update `APP_URL` to the same URL.

## 8. Open the installer

Visit:

```text
https://your-domain.example/install
```

Resolve the Requirements step first, then complete environment, database, mail/storage, campaign scope/geography, campaign identity, geography setup and Super Administrator configuration.

## 9. Queues

Campaign Manager's first-run installer may operate with safe synchronous processing. If you later configure an asynchronous Laravel queue driver, also configure a persistent worker under your process manager.

A generic worker command is:

```bash
php artisan queue:work
```

For production, run it under a service/process manager rather than an interactive SSH session. Choose restart, retry, timeout and concurrency settings appropriate to the enabled workload and your server capacity.

After deploying application updates, restart long-running queue workers using the release/deployment procedure appropriate to your environment.

## 10. Scheduler

If enabled Campaign Manager features require scheduled Laravel tasks, configure cron to invoke Laravel's scheduler every minute:

```cron
* * * * * cd /var/www/campaign-manager && php artisan schedule:run >> /dev/null 2>&1
```

Use the correct CLI PHP binary for your server.

## 11. Storage/media

If the application enables publicly served uploaded media, complete the storage setup requested by the installer/application and verify generated media URLs over HTTPS.

Do not make the entire `storage/` tree publicly browsable.

## 12. Production verification

Check:

- HTTPS and redirects
- Super Administrator login
- correct campaign scope and geography
- dashboard loading
- media/uploads where enabled
- mail delivery if configured
- queue worker if asynchronous queues are enabled
- scheduler if required
- error log access
- database and file backups
- disk space and database capacity

## 13. Operational security

Recommended basics:

- firewall only required public/admin ports
- SSH keys instead of password-only SSH where practical
- restricted database exposure
- `APP_DEBUG=false`
- regular security updates
- off-server backups
- monitoring for disk, database, PHP-FPM and web-server errors
- no credentials or campaign records in public support tickets
