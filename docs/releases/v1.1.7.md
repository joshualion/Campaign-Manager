# Campaign Manager v1.1.7

This release improves secure automatic-update checkout, fixes Volunteer Group and Age Grade settings returning HTTP 500 on case-sensitive hosting, and fixes election results pages for new elections.

- Accept only explicitly trusted HTTPS Portal checkout origins, including the official canonical and approved `www` origins. Validate the registered installation, campaign scope, target version and package checksum before opening checkout.
- Support installation-bound, signed return links from the Customer Portal. Recheck registration, coverage and the signed release after returning; the customer confirms before installation starts.
- Keep pending bank transfers pending until approved. Checking for updates and manual downloads remain free; automatic package downloads require confirmed coverage.
- Clearly offer **Automatic Update** and **Manual Update** in Official Updates.
- Fix Volunteer Group and Age Grade list, add and edit pages, optional descriptions and redirects. Prevent deleting age grades that still contain users.
- Show a safe empty results page before votes arrive at every administrator level, from Super Admin through Polling Unit Admin. Use the actual campaign/geographic scope in headings without requiring an optional country record. Received results and charts continue to respect geographic access boundaries.
- Preserve existing configuration, deployment identity, accounts, uploads and campaign data during managed updates. Backups, approved migrations, interruption recovery and health checks remain required.

## What existing customers should do

Open **Official Updates → Check for updates**. Choose **Automatic Update** to review your campaign's current coverage price or use existing active coverage. After verified payment, return to your installation, refresh coverage and confirm the update. Checking alone does not download or install the package. A pending transfer does not activate coverage.

The central Portal checkout-origin correction is already deployed and is intended to unblock existing v1.1.5 checkouts. An older installation's updater code changes only when upgraded or when its official signed bootstrap is installed. To use the v1.1.7 updater on an older installation, follow the [automatic-update guide](https://github.com/joshualion/Campaign-Manager/blob/main/docs/automatic-updates.md): download this release's bootstrap and checksum, verify them, extract outside the web root, and run `php bootstrap-install.php /absolute/path/to/existing/core`. Use `--replace-bootstrap` for an existing bridge; active updates and unrecovered jobs must be resolved first. Sign in as Super Admin and open `/campaign-update-bootstrap.php`.

Alternatively, choose **Manual Update** for the official release download and follow the manual upgrade guide. Software downloads remain free.

## Validation and limits

Publication requires PHP 8.2/8.3 lint, application tests, frontend build and dependency audits; MySQL 8.0 and MariaDB 10.11/11.4 backup and recovery checks on both PHP versions; verified signatures/checksums; and isolated signed-bootstrap upgrade rehearsals from official v1.1.3, v1.1.4, v1.1.5 and v1.1.6 archives. These rehearsals verify backups, managed replacement, migrations, installed version, credentials, configuration and uploads. Entitlement is stubbed only in the disposable rehearsals. No real customer payment or production automatic upgrade is claimed by these checks.

Existing v1.1.6 assets remain unchanged. Hosts must pass readiness checks; failed safety checks stop the update. Preserve private backups and use the verified recovery procedure if rollback is needed.
