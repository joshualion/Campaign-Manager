# Campaign Manager v1.1.8

This release repairs the recovery updater on existing installations and simplifies automatic updating.

- Fixes the bootstrap HTTP 500, malformed login/dashboard redirects and broken asset addresses. Preserves the original request, session and CSRF protections.
- Presents **Check for Updates**, **Update Automatically** and **Manual Update**. Manual downloads remain free.
- Checks registration, the signed release and coverage internally. Without coverage, opens secure Portal checkout. After verified payment, returns to the installation and requests explicit installation confirmation.
- Binds checkout return navigation to the registered installation, release and original browser session using an expiring signed state. Navigation never activates coverage or installs an update.
- Shows a clear registration summary. Sensitive domain/contact operations are kept under **Manage Registration Details**. Missing contact ownership proof uses one guided verification flow; existing proof is not waived or repeated.
- Preserves backup, migration approval, interruption recovery, health checks and installed-version verification. Pending bank transfers remain pending until approved.

## Existing customers

Open **Official Updates**, check for updates and choose **Update Automatically**. If payment is needed, complete checkout with the Portal account belonging to the installation's verified registered email. Return to Campaign Manager and confirm installation when ready. Another authorized Super Admin can use coverage that is already active.

If your older updater cannot start, follow [the recovery instructions](https://github.com/joshualion/Campaign-Manager/blob/main/docs/updater-recovery-v1.1.8.md). The recovery bootstrap repairs the updater; it does not upgrade Core merely by being installed or opened.

## Release conditions

Deploy the compatible Portal checkout-return change before making this Core release available. Build with the established production signing identity. Require the application/database checks and both packaged HTTP and upgrade rehearsals before publication. Keep published v1.1.6 and v1.1.7 assets unchanged.

Local rehearsals use disposable installations and test authorization; they do not prove a real customer payment or production automatic upgrade. Owner approval and the production acceptance test remain required.
