# Campaign Manager Installation Guide

This guide covers the normal Community / Self-Hosted path from an official GitHub release to a verified Campaign Manager installation.

> Campaign Manager Community is free to download and use. No software licence key or remote software activation is required. A QuickStart Geography Provisioning Key is optional and is only used when you purchase the QuickStart geography convenience service.

## 1. Before you start

Prepare:

- a domain or subdomain for the installation
- a properly configured PHP web server
- a MySQL/MariaDB-compatible database environment supported by the release
- a database and dedicated database user
- SSL/TLS for the public domain
- access to create/edit `.env`
- permission to set the website document root to the application's `/public` directory
- write access for the web-server user to Laravel's writable directories

### Runtime requirements

The public distribution repository does not publish the private dependency manifest, so this guide deliberately does **not** guess a PHP version or PHP extension list.

The authoritative compatibility check is the **Requirements** step shipped with the installer in the release you are deploying. Before production use:

1. select a PHP version supported by your hosting environment;
2. open `/install`;
3. review every installer requirement;
4. enable/adjust PHP extensions or limits reported as missing;
5. do not continue past critical requirement failures.

If you are deploying on managed hosting, ask the provider to enable any extension reported by the installer rather than assuming a generic Laravel list is sufficient.

## 2. Download the official release

Use the official GitHub Releases page:

- [Latest release](https://github.com/joshualion/Campaign-Manager/releases/latest)
- [All releases](https://github.com/joshualion/Campaign-Manager/releases)

The production package is:

```text
campaign-manager.zip
```

Use the release asset, not GitHub's automatically generated source-code ZIP/TAR archives.

## 3. Upload and extract

Upload `campaign-manager.zip` to the intended application directory and extract it.

A typical layout is:

```text
/home/account/apps/campaign-manager/
    app/
    bootstrap/
    config/
    public/
    resources/
    routes/
    storage/
    .env.example
    artisan
    ...
```

Keep the Laravel application outside the publicly exposed document root where your hosting model allows it.

## 4. Set the document root correctly

The web server must serve the application's:

```text
/public
```

directory as the website document root.

Do **not** expose the application root, `.env`, `storage`, configuration files or framework directories directly to the web.

Examples:

```text
Document root: /home/account/apps/campaign-manager/public
```

or on a VPS:

```text
/var/www/campaign-manager/public
```

## 5. Create the database

Create:

- a new database;
- a dedicated database user;
- a strong password;
- appropriate privileges for that user on the Campaign Manager database.

Keep these details ready for the installer:

```text
DB_HOST
DB_PORT
DB_DATABASE
DB_USERNAME
DB_PASSWORD
```

Do not reuse a highly privileged database administrator account for routine application access.

## 6. Configure the environment

The release includes `.env.example`. Depending on your hosting workflow, either let the installer guide environment setup or create `.env` from the example first.

Where shell access is available:

```bash
cp .env.example .env
```

Set the correct application URL, environment, database and mail values through the installer/environment workflow.

If the deployment requires an application key and one has not been generated by the installer, use:

```bash
php artisan key:generate
```

Never share the generated `APP_KEY` publicly.

### APP_URL

Set `APP_URL` to the real HTTPS URL users will access, for example:

```text
https://campaign.example.org
```

Incorrect `APP_URL` values can cause broken redirects, generated links, media URLs or callback URLs.

## 7. Configure writable directories

The web-server process must be able to write to:

```text
storage/
bootstrap/cache/
```

Use ownership/group permissions appropriate to your server. Avoid `chmod 777` as a normal deployment solution.

On a VPS, the exact user/group depends on your PHP/web-server setup. On cPanel, account ownership and hosting defaults normally differ from a VPS, so follow the hosting provider's safe permission model.

## 8. SSL and domain

Point the domain/subdomain to the server and install a valid TLS certificate before production use.

After SSL is enabled:

- confirm the site loads over `https://`;
- ensure `APP_URL` uses HTTPS;
- redirect plain HTTP to HTTPS at the web-server/hosting level where appropriate.

## 9. Open the installer

Visit:

```text
https://your-domain.com/install
```

The installer guides you through the current first-run flow, including:

1. Welcome
2. System requirements
3. Environment configuration
4. Database setup
5. Mail configuration
6. Storage setup
7. Campaign scope
8. Relevant campaign geography
9. Campaign identity
10. Geography setup method
11. Super Administrator setup
12. Installation/provisioning completion

The precise labels may evolve between releases; follow the installer bundled with your version.

## 10. Choose campaign scope

Supported high-level scopes are:

- Presidential / National
- Governorship / State
- Senatorial
- Federal Constituency
- Local Government / Chairmanship

See [Campaign Scopes](campaign-scopes.md).

## 11. Choose geography setup

You have two paths:

### Manual Geography Configuration — free

Configure the required campaign geography yourself. No provisioning key is required.

### QuickStart Geography Provisioning — optional paid convenience

If you purchased QuickStart, enter the QuickStart Geography Provisioning Key when prompted. The key authorises geography provisioning for the purchased scope/geography only; it is **not** a software licence key.

See [Geography Setup](geography-setup.md) and [QuickStart](quickstart.md).

## 12. Post-install verification

Before onboarding real campaign data, verify:

- the login page loads over HTTPS;
- the Super Administrator can sign in;
- the configured campaign name/scope is correct;
- campaign geography appears as expected for the chosen setup method;
- dashboards load without server errors;
- uploads/media work where enabled;
- mail configuration works if email features are required;
- queue processing works if you choose an asynchronous queue configuration;
- scheduled tasks are configured if your enabled features require Laravel's scheduler;
- backups are configured for the database and user-generated files;
- server error logs are accessible to the technical administrator.

## 13. Production hygiene

Before real-world use:

- keep `APP_DEBUG` disabled in production;
- restrict server/database access;
- use strong administrator credentials;
- keep regular off-server backups;
- monitor storage capacity and logs;
- apply supported updates after reading release notes;
- never publish `.env`, database dumps, campaign records or QuickStart keys.
