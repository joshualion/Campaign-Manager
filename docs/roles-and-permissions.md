# Roles and Permissions

Campaign Manager uses campaign-specific roles and permissions so access can follow the political and electoral structure of the campaign.

The live Super Admin demo exposes **23 roles** spanning national, regional, state, senatorial, federal constituency, LGA, ward, polling-unit and member responsibilities.

## Verified administration surfaces

The **Roles & Permission** area includes:

- **Roles Permissions**
- **Assign Roles Permission**
- **Manage Permissions**
- **Manage Roles**

Manage Roles displays role, guard and group information. Manage Permissions exposes permission, guard and group information. Roles Permissions shows the permissions assigned to each role.

## Campaign hierarchy

The verified role set covers responsibilities across the campaign hierarchy, including national/candidate, regional, state, senatorial, federal constituency, LGA, ward, polling-unit and member levels.

This allows access control to follow political structure instead of relying on one generic administrator/member split.

## Permission coverage

The inspected permission catalogue includes:

- election review capabilities;
- SMS view/compose/send/report/settings/wallet/credit capabilities;
- create/read/update/delete permission groups across administrative levels.

Exact permission assignments depend on how the deployment administrator configures the roles.

## Security guidance

Apply least privilege. Give each role only the capabilities required for its campaign responsibility.

When documenting or reporting access-control issues publicly, do not include real campaign user identities, contact details, credentials, tokens or private role assignments tied to identifiable people.
